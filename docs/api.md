# HTTP API and Python client

Start the server (Studio at `/`, interactive API docs at `/docs`):

```bash
python -m vectorforge serve --data ./data                    # vectors only
python -m vectorforge serve --data ./data --embedder gemini  # + text search (GEMINI_API_KEY)
```

On Windows, call `python -m vectorforge` rather than the `vectorforge.exe`
launcher if App Control blocks unsigned executables.

## Endpoints

| Method | Path | Body / query | Returns |
|---|---|---|---|
| GET | `/healthz` | | version, embedder |
| GET | `/collections` | | info for every collection |
| POST | `/collections` | `name, dim, metric, index, params, storage` | info (201) |
| GET | `/collections/{name}` | | info: points, holes, index stats, WAL state, payload fields |
| DELETE | `/collections/{name}` | | |
| PUT | `/collections/{name}/points` | `points: [{id, vector, payload}]` | count, ms |
| POST | `/collections/{name}/points/get` | `ids, with_vectors` | points (null where missing) |
| POST | `/collections/{name}/points/delete` | `ids` | count deleted |
| GET | `/collections/{name}/points` | `after, limit, with_vectors` | a page in ID order + `next` |
| POST | `/collections/{name}/search` | one of `vector`, `text`, `query_id`, `random`; `k, filter, exact, ef, nprobe, rerank, compare_exact` | hits, plan, ms (+ exact hits and recall) |
| POST | `/collections/{name}/search/batch` | `vectors, k, filter, ...` | results |
| POST | `/collections/{name}/explain` | `k, filter, exact, ef, nprobe` | the plan, without searching |
| POST | `/collections/{name}/checkpoint` | | info after checkpoint, ms |
| POST | `/collections/{name}/train` | | retrain IVF-PQ on current data |
| POST | `/collections/{name}/texts` | `texts, payloads` | embed and upsert (needs `--embedder`) |
| GET | `/collections/{name}/inspect` | | HNSW layers / degrees, or IVF list sizes |
| POST | `/collections/{name}/inspect/trace` | query as in search; `ef` or `nprobe`; `sample` | 2-D PCA map with the query's path |
| GET | `/benchmarks` | | result files from `--results` |

Errors: 400 for bad input (wrong dimension, bad filter, unknown setting),
404 for a missing collection or point, 409 when a collection exists.

Point IDs are integers from 0 to 2^63 - 1. JavaScript loses precision
above 2^53, so IDs generated by VectorForge (text and LangChain IDs) stay
below that.

## Python client

```python
from vectorforge.client import Client

vf = Client("http://127.0.0.1:8000")
docs = vf.create_collection("docs", dim=768, metric="cosine")
docs.upsert(ids, vectors, payloads)              # batched, 1,000 per request
hits = docs.search(q, k=10, filter={"lang": "te"})
docs.explain(filter={"lang": "te"})
```

`RemoteCollection` has the same methods and return types (`Point`,
`ScoredPoint`) as the embedded `Collection`, so code can move between the
two by changing one line.

Vectors travel as JSON lists. That is simple and debuggable but costs
roughly 10x the bytes of binary float32; a binary upsert route is the
obvious next step if ingest over HTTP becomes the bottleneck.
